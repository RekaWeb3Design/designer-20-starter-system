# Journey Mapper

## Process
1. Read /output/ux-research/personas.md — one journey per persona.
2. For each journey, map these columns per stage:
   - Stage name (awareness → consideration → action → after)
   - Actions (what the user actually does)
   - Thoughts & questions
   - Emotions (with the low points highlighted)
   - Touchpoints (where it happens: site section, email, phone...)
   - Opportunities (what the product could do better HERE)
3. Mark unsupported claims with [ASSUMPTION].

## Quality bar
- Journeys must differ where the personas differ — if two journeys are
  identical, say so explicitly instead of inventing differences.
- Every stage needs at least one concrete opportunity, phrased as a
  design decision (not "improve UX").
- Tag [ASSUMPTION] selectively: only claims whose falsity would change
  a design decision. If every sentence carries the tag, the signal is
  lost — put context-level assumptions in ONE note at the top instead.

## Output
